# 管理员指南

## 管理入口与权限

使用具有 `PLATFORM_ADMIN` 角色的账号登录管理系统，进入“平台资源管理”。扩展页面路径为 `/mis/extensions/platform-resources`。

该页面汇总全局资源预留、宿主机容量、实例归属、持久数据、计算开户与操作记录。角色以每次请求的平台认证结果为准；普通用户直接访问全局 API 会收到 403。普通用户的容量接口仅返回本人额度以及申请所需的 GPU 型号与运行环境信息，不返回宿主机与全局容量。

管理系统不提供用户交互式工作空间入口。需要申请自己的环境时，返回门户。全局资源页当前为只读查看；调整配额或处理宿主机故障需要运维人员修改配置或排障，不能假定页面已提供管理员代用户释放功能。

## 查看操作与分页

实例、计算开户、数据卷、工作空间操作和事件列表分别分页。个人控制台中的操作和事件也各自分页，默认每页 20 条，每页最多 100 条，可查看总数并切换页码。

排障时记录用户名、实例编号、操作类型、时间和诊断编号。操作请求已接受只表示排队成功，应继续查看执行阶段与最终结果；失败详情和诊断编号可关联扩展服务日志。

## 工作空间资源策略

工作空间配置位于配套部署仓库的 `hitper/capacity.yaml`：

| 配置块 | 内容 |
| --- | --- |
| `user` | 每用户实例数、CPU、GPU、内存和磁盘预留上限 |
| `global` | 平台可预留的资源总量 |
| `host` | 为系统服务保留的 CPU、内存、磁盘和 GPU |
| `gpu_devices` | 允许工作空间分配的 GPU UUID 白名单 |

当前每用户上限是 3 个实例、8 核 CPU、1 张 GPU、16896 MiB 内存预留和 150 GiB 磁盘预留。平台全局预留上限为 16 核 CPU、2 张 GPU、32768 MiB 内存和 200 GiB 磁盘；还受真实主机容量和系统保留资源约束。

修改配置不会自动调整已有实例的运行时限制，也不会回收已有实例。配置在服务启动时读取，修改后应重新启动扩展服务并检查容量页面。降低上限前先核对现有预留，不要将资源统计和实际运行限制混为一谈。

工作空间 GPU 必须专供该资源池使用，不应再由其他调度器分配。分配逻辑排除已有实例预留和已运行计算进程，但不能替代多个调度器之间的统一资源协调。Slurm 资源由集群策略另行管理。

## 注册与 Slurm 策略

当前注册后立即开通普通平台账号，计算开户在后台执行。管理员可查看失败步骤和日志；普通用户可在自己的页面重试。保留用户名不可自助注册，注册流程不会赋予管理员角色。

计算开户与体验策略主要涉及：

- `hitper/compute.yaml`：集群、运维连接目标、分区、QOS、资源和初始体验额度。
- `config/clusters/hpc01.yaml` 的 `jobPolicies`：门户的账户前缀、分区与资源限制。
- Slurm 的分区、QOS 与账户关联：调度器侧最终执行的限制。

调整策略要同步核对三处。初始化脚本会修改集群配置，不能只修改网页参数就认为集群策略已更新。原有账户的关联也应单独验证。

## 数据与访问管理

释放和到期回收保留数据卷，卷仍计入磁盘额度。删除数据前应确认用户是否仍需保留；当前没有自动快照或平台自动备份。容器 `/home/hitper` 和虚拟机系统盘的备份方式不同，详见[部署与维护](./deployment.md)。

工作空间仅使用用户公钥认证；平台不收集用户私钥，也不把用户公钥同步到集群节点。集群文件与作业服务使用单独的运维访问策略，普通用户的直接 SSH 和网页 Shell 保持关闭。

## 监控与维护

工作空间个人用量按运行实例采样 CPU、内存和实例时长，最近 7 天显示在个人页；聚合数据保留 90 天。当前没有把 GPU 卡时纳入该用量汇总，也不把采样值作为收费账单。

全局监控由 Prometheus 和 Grafana 展示。当前扩展告警覆盖服务不可用、操作长时间未完成、预留容量偏高、开户 / 公钥同步失败指标和磁盘不足；个人公钥同步到节点的功能已禁用。告警接收方式沿用现有部署，不代表已配置邮件等外部通知。

常用只读排障命令见[部署与维护](./deployment.md)，用户侧故障现象见[常见问题](./troubleshooting.md)。
