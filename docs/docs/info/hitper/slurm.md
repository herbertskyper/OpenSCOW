# Slurm 与交互式应用

## 账户、作业与工作空间的关系

平台账号用于网页认证；计算账户用于 Slurm 作业的归属、权限、额度和记账。自助注册的计算账户通常命名为 `hp_用户名`。只有作业进入调度并运行后，才会占用对应 Slurm 资源。

云工作空间另从专用 Docker / KVM 资源池申请资源，不会自动加入 Slurm，也不会因为开通计算账户就生成一个 SSH 环境。当前部署的工作空间 GPU 位于独立部署机，与 Slurm 计算节点 GPU 分开管理。

## 通过网页提交作业

1. 在云工作空间页确认“我的超算账户”已就绪。
2. 通过门户文件管理上传脚本、程序和输入数据，确认集群侧工作目录。
3. 在作业提交页选择集群、账户、分区、QOS，以及 CPU、内存、GPU 和运行时间。
4. 填写实际运行命令并提交。
5. 在运行中 / 已结束作业列表查看状态，使用作业详情中的输出路径检查标准输出和错误信息。
6. 提前结束任务时，通过作业管理取消对应作业。

不要把工作空间里的 `/home/hitper` 当作 Slurm 集群个人目录；两者没有自动挂载或同步关系。

## 当前体验账户策略

| 作业类型 | 分区 | QOS | CPU | 内存 | GPU | 最长时间 |
| --- | --- | --- | --- | --- | --- | --- |
| CPU | `trial` | `hitper_trial` | 最多 2 核 | 最多 4 GiB | 不允许申请 | 30 分钟 |
| GPU | `trial_gpu` | `hitper_gpu` | 最多 2 核 | 最多 4 GiB | 最多 1 张 | 30 分钟 |

两个体验 QOS 分别设置每用户最多 2 个运行作业、8 个提交作业；这不是跨两个 QOS 合并的全局作业数上限。同一 QOS 内还受每用户 CPU、内存和 GPU 并发总额度约束，不能把上表资源上限理解为每个作业都能叠加使用。实际限制以账户关联、QOS、分区和门户校验共同执行的结果为准，管理员可调整。

CPU 分区不会携带隐藏的 GPU 默认值。选择 GPU 任务时，应明确使用 GPU 分区、匹配的 QOS 和 GPU 数量；提交被拒绝时，先检查这些字段，而不是尝试绕过平台登录节点运行程序。

## 命令示例

下面是可填入网页作业提交页的最小 CPU 命令，资源字段在网页选择：

```sh
hostname
date
python3 -c 'print(sum(range(1000000)))'
```

GPU 作业可先用以下命令检查设备是否可见：

```sh
nvidia-smi -L
```

Slurm 计算节点上的软件环境由集群管理员配置；工作空间 PyTorch 镜像不会自动用于 Slurm 作业。运行模型前需确认集群侧 Python、CUDA、依赖与数据路径。

## 交互式应用

在门户“交互式工作空间”进入已有应用，选择应用模板和资源后提交会话。应用通过 Slurm 启动，等待资源分配后再使用页面提供的连接入口。VSCode、Emacs 保留原有配置，不需要为了使用云工作空间重新适配。

关闭浏览器页面不保证作业或会话已结束。完成任务后，在应用会话或作业列表中确认结束，避免继续占用调度资源。

## 费用与访问边界

当前自助计算开户会发放一次 10 元平台体验记账额度，不涉及实际付款。Slurm 作业沿用平台现有计费及冻结策略；账户余额不足或被冻结可能影响作业提交。

云工作空间目前不从该余额扣费，个人工作空间用量是采样统计。普通用户不能直接 SSH 登录集群节点，也没有登录节点网页 Shell 或登录桌面入口；文件管理和作业提交由受控的平台服务完成。
