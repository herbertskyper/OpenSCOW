# HITPER 使用指南

本组文档介绍 HITPER 当前部署的使用方法与运行边界。菜单名称、模板和额度以平台实际配置为准；原有通用文档中的登录节点 Shell、演示账号等内容不代表当前部署已开放相同能力。

## 先分清四个概念

| 名称 | 用途 | 是否直接分配计算资源 |
| --- | --- | --- |
| 平台账号 | 网页登录、身份与权限 | 否 |
| 我的超算账户 | Slurm 账户、账户成员关系、额度和计费状态 | 开通账户时不分配资源，提交作业后由 Slurm 调度 |
| 交互式应用 | 使用已有应用模板，在集群上启动应用会话 | 通过 Slurm 作业申请 |
| 云工作空间 | 申请可通过独立 SSH 端口访问的 Docker / KVM 环境 | 通过工作空间配额和资源池分配 |

## 当前开放的环境

- PyTorch 2.1.1 / CUDA 12.1 容器，可申请 GPU。
- Ubuntu 22.04 / CUDA 11.8 Docker 容器，可申请 GPU。
- Alpine 3.20 Docker 容器，仅支持 CPU。
- Ubuntu 24.04 虚拟机，仅支持 CPU，支持虚拟机内 sudo。
- 原有 VSCode、Emacs 等交互式应用继续使用原有入口与集群配置。

GPU 容器按整卡分配设备；CPU 与内存受运行时限额约束。工作空间的 CPU 数量表示可用计算配额，不表示 CPU 核心已被物理独占绑定。

## 数据和资源规则

停止实例不会暂停到期时间，也不会归还 CPU、GPU、内存的预留额度。释放或到期回收成功后，计算额度归还，持久数据卷保留；删除数据卷是另外一步不可恢复的操作。

Docker 仅保留 `/home/hitper`，虚拟机保留整个系统盘。工作空间和 Slurm 集群个人目录是两套存储，平台不会自动同步文件。个人用量为采样估算，目前不作为工作空间收费账单。

## 管理与项目组成

普通用户在门户使用工作空间；平台管理员在管理系统的“平台资源管理”查看全局信息。管理系统不提供用户交互式工作空间申请入口。

网页与服务端源码位于当前仓库，注册与工作空间扩展位于配套部署仓库的 `hitper/` 目录。完整部署需要两者配合，详见[部署与维护](./deployment.md)。
